# 听见你｜初赛方案

## 作品标题

听见你——声音优先的无障碍交友

## 500 字内作品简介

听见你不是给视障用户做一个“特殊版交友软件”，而是把声音变成认识彼此的主入口。视障用户难以依赖照片判断资料，照片焦虑者也常在第一句话之前被评价。

用户录制四段真实回答，平台根据共同兴趣、交流方式、活动偏好与无障碍需求进行透明匹配。AI 只生成可选文字摘要和具体破冰建议，不改声、不代聊，也不推测人格。双方确认后，系统生成可朗读的公共空间见面卡，提供无障碍路线、30 分钟轻柔提醒和无需解释的离场方式。

公益目标不是制造更多滑动，而是帮助一个人安全、舒适地完成一次真实连接。

## 目标用户

- 主要用户：视障、低视力或其他无法依赖照片资料的人。
- 共同用户：有照片焦虑、社交焦虑或低社交电量的人。
- 活动合作方：学校心理中心、学生社团、团委和图书馆。

## 核心体验

1. **留下声音坐标**：选择期待的关系、交流方式、小组大小、兴趣和无障碍需求。
2. **回答四件小事**：最近开心的事、理想的一个下午、希望朋友怎样相处、想尝试的新事情。
3. **听见朋友**：播放本人介绍，同时看到共同点与推荐理由。
4. **安全见面**：双方确认公共地点，形成可朗读路线，并提供提醒与中性离场机制。

## AI 的具体职责

- 将本人允许的语音转成可编辑文字，提高读屏与搜索体验。
- 从明确选择的兴趣和需求中生成推荐解释，保证理由可核对。
- 生成低压力破冰问题和线下活动流程。
- 在用户明确请求时重写文字摘要，但不改动原录音。

AI 不负责：生成或克隆声音、替用户回复、判断人格和心理健康、预测恋爱成功概率、自动交换联系方式。

## 技术实现

- 前端：原生 Web 应用，使用 `MediaRecorder` 录音、Web Speech API 可选转写与朗读。
- 匹配：基于兴趣交集、关系方向、交流方式、小组偏好和无障碍需求的可解释评分。
- 安全副驾驶：结构化见面卡、定时提醒、无障碍路线和中性离场消息。
- 当前原型：无后端依赖，用户资料保存在本机，便于稳定演示。
- 正式版：接入账号与身份验证、对象存储、向量检索、举报审核和双方同意记录。

## 可行性

- 初赛版本已实现完整三步主流程，并能直接在浏览器运行。
- 音频、匹配、资料详情和见面规划均为真实可操作交互。
- 浏览器不支持录音或语音转写时，保留完整文字流程。
- 决赛前优先完善：候选人真实录音、双方确认、举报和活动同步。

## 公益效果指标

- 从完成资料到愿意发起真实活动的转化率。
- 首次公共空间活动完成率。
- 活动后“感到被理解”“感到安全”和“愿意再次参加”的自评变化。
- 读屏和纯键盘用户完成主流程的比例。
- 活动后举报、拉黑或请求撤回资料的比例。

不以停留时长、滑动次数或每日活跃时长作为成功指标。

## 90 秒现场演示

**0—15 秒：提出问题**

“主流交友产品让你先看照片。可是看不见照片的人，以及害怕被照片评价的人，怎样开口认识另一个人？”

**15—40 秒：听见一个人**

打开匹配页，点击“听见周予安”。展示四段具体回答，而不是外貌标签。

**40—60 秒：证明 AI 没有乱猜**

指出三条推荐理由都来自双方主动选择的兴趣、交流方式和活动需求。AI 只帮助表达与安排，不判断人格。

**60—85 秒：把匹配变成安全行动**

点击“约一次轻松见面”，生成校园书店路线、30 分钟提醒和无障碍休息点。演示“我需要先离开”。

**85—90 秒：收束**

“听见你追求的不是让用户多停一会儿，而是让一次真实连接安全发生。”

## 现场风险预案

- 网络不稳定：完整核心流程可离线运行，不依赖外部 AI API。
- 麦克风不可用：提前准备演示资料，并保留文字填写路径。
- 浏览器朗读不可用：评委可直接阅读转写与推荐理由。
- 投屏字号较小：使用内置“放大文字”和“高对比”按钮。
